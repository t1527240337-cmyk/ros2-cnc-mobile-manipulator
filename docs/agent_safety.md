# LLM Agent 安全设计

## AgentCommand 白名单

Agent 可返回十三种高层操作：提交订单、查询工厂、查询任务、启动/停止/查询自动生产、
暂停/恢复/取消任务、请求单台机床受控 HOLD/RESUME、解释故障、列出能力。订单数量为
1–3，机床只能是 `machine_1..3`。这个上限来自当前 Gazebo 中 3 个可追溯原料实体和
3 件整单物理验收，不允许 LLM 或 MCP 声明未建模的额外库存。

停止自动生产是 drain-stop：禁止创建新订单，但不打断正在搬运的零件。暂停或取消当前
订单必须使用独立任务控制命令，且仍只在物理步骤安全边界生效。

以下能力永远不作为 Agent 工具：

- `/cmd_vel`、导航局部控制器和 docking 速度；
- 关节轨迹、MoveIt Servo 和夹爪电机命令；
- 机床开门、关门、启动、故障复位和主轴输出；
- 急停触发或复位、安全门锁旁路；
- 电池状态、机床状态和零件归属的直接写入。

`HOLD_MACHINE` 只是向确定性机床控制器请求受控进给保持；控制器仍可因状态或互锁拒绝。

## Web 与 MCP 共用的执行边界

`/factory_agent/command` 是 Web、MCP 和其他结构化客户端共用的唯一 Agent ROS 入口。
它再次用 `AgentCommand` 校验参数，并等待底层 Service 或 Action 明确接受后才返回成功。
查询命令立即处理，不进入机器人生产队列。

MCP 层只是一组上述白名单操作的适配器，不能通过自定义工具名扩大权限。返回值同时
包含人类可读 `message` 和机器可读 `data_json`。每次请求还会写入追加式 JSONL 审计，
记录请求 ID、来源、操作、订单 ID 和最终接受结果。详见
[`mcp_agent.md`](mcp_agent.md)。

## 知识库与结构化输出

小规模 SOP 使用仓库内可审计 YAML 知识库。检索器按中文关键词选出最相关条目，并始终
补入 Agent 权限边界；这些内容与实时工厂状态一起进入 LLM 上下文。知识库只提供流程与
解释，实时状态必须来自 ROS 2 服务，不能由模型记忆猜测。

LLM 输出必须通过 Pydantic/JSON Schema，允许一次格式修复，8 秒超时后使用规则解析器。
数量缺失时要求澄清，不默认加工全部库存。对于当前几十条 SOP，透明关键词检索比引入
向量数据库更便于调试；知识增长到数百条后再替换检索实现，`AgentCommand` 契约保持不变。
